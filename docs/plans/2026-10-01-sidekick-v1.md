# Buds Sidekick v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, in-session). Steps use checkbox syntax.
> Note: the repo is not a git repository, so there are no commit steps. Each task ends with its test run.

**Goal:** Voice-aware personal assistant on Galaxy Buds FE + MacBook: conversation capture with speaker identity, memory/RAG over
what each person said, manual + auto guidance, replay, Telugu<->English translation, remote-control use of the buds, and a dashboard.

**Architecture:** An event-driven pipeline: `CaptureSource -> RingBuffer + Segmenter -> (SegmentTranscriber, SpeakerEngine) -> Store/Memory -> Policy/Brain -> OutputArbiter`.
A `ModeController` owns the mode (Idle/Manual/Conversation/Auto/Private) and the *placement* (ear vs remote, from wear state), which selects
the capture device, output device and gesture profile. A FastAPI dashboard consumes the same `EventBus`. Everything is local; every
external dependency (Ollama, Whisper, sherpa-onnx, sounddevice, `say`) sits behind a small interface with a fake for tests.

**Tech Stack:** Python 3.14, asyncio, SQLite, FastAPI + vanilla JS, faster-whisper, sherpa-onnx (WeSpeaker ONNX), Ollama (qwen3.5:4b-mlx, gemma4:12b-mlx, nomic-embed-text), macOS `say`, sounddevice, budslab (lab package).

**Spec:** `/spec.md` (+ Addendum v1.1 appended there: English conversations, Telugu<->English translation, remote mode, dashboard).

## Verified facts that shaped this plan (checked 2026-10-01 on this Mac)
- Speaker model `wespeaker_en_voxceleb_resnet34_LM.onnx` (sherpa-onnx, 26 MB, dim 256): same voice cos 0.85-0.94, different voices <= 0.57 (synthetic voices; real voices untested).
- Telugu: macOS voice **Geeta (te_IN)** exists. Translation en->te correct only on `gemma4:12b-mlx` (qwen 4B/9B changed the meaning); te->en fine on all (4B ~1 s).
- Telugu **speech recognition is NOT usable**: Whisper small/medium identify language `te` but transcribe garbage (medium also 107 s per 6 s clip on CPU); Apple Speech has no `te-IN`. => Telugu speech input is an experimental, pluggable backend; Telugu text input and English-speech->Telugu output are first-class.
- Apple M3 / 16 GB: keep one big model resident at a time (4B for chat, 12B on demand for translation).

## Global Constraints
- Local-only: no network calls in the audio/identity/memory path (model downloads happen at install time only). Cloud LLM is not in v1.
- Audio ring buffer is RAM-only and bounded (5-60 s, default 8). Unknown speakers are never persisted. `forget(person)` removes voiceprint, segments, audio files, facts, vectors.
- Only the lab's allowlisted buds commands may be sent; the app restores noise mode / touchpad settings it changed.
- Python >= 3.11 syntax; no new heavy deps beyond those listed (no torch).
- All new behaviour has a fake/simulated path so tests need no hardware, no network, no human.

## Review Focus
- Silence / empty / music segments must not create people, facts or hints.
- Two speakers talking at once, or a 0.3 s interjection: no crash, label "unknown", no wrong named hint.
- Ollama down or slow: manual answers fall back to RuleAgent with an honest message; auto mode goes quiet; nothing blocks audio.
- Buds disconnect/reconnect mid-conversation: conversation continues from Mac mic (remote placement), no orphaned streams.
- Telugu text with mixed English / empty / very long input to the translator; TTS voice missing.
- `forget` while a conversation is live; DB rows referencing a deleted person.

## File structure (all under `assistant/buds_assistant/`)
| File | Responsibility |
|---|---|
| `events.py` | `EventBus` (sync publish, async subscribers/WS queues), event dict schema |
| `config.py` | `Config` dataclass loaded from `sidekick.yaml` (models, thresholds, languages, devices, retention) |
| `store.py` | SQLite schema + CRUD: people, voice_samples, conversations, segments, facts, hints, audit; `forget()`; retention sweep |
| `capture.py` | `CaptureSource` protocol, `MicSource`, `FileSource`, `RingBuffer` |
| `segmenter.py` | Streaming utterance segmenter (energy VAD with pre-roll) -> `Segment` |
| `speaker.py` | `SpeakerEngine`: embed (sherpa), enrol, identify (open-set), provisional clusters, name/merge/correct |
| `transcribe.py` | `SegmentTranscriber` (Whisper en; experimental te), language gate, fakes |
| `llm.py` | `OllamaClient` (chat, embed, timeouts, model keep-alive), `FakeLLM` |
| `memory.py` | Embedding index over segments, retrieval, fact/commitment extraction, dossier, conversation window |
| `translate.py` | `Translator` en<->te (gemma4), language detection by script, glossary |
| `brain.py` | `Brain.respond()`: intent routing (rules) then RAG answer; spoken-style; sources |
| `policy.py` | Auto-mode triggers, gating, feedback, rate limits |
| `output.py` | `OutputArbiter`: priorities, barge-in, ducking, `SayRenderTTS`, device routing, replay playback |
| `modes.py` | `ModeController`: modes, placement (ear/remote), gesture profiles, action dispatch |
| `pipeline.py` | `ConversationPipeline`: wires capture->segments->stt+speaker->store->policy |
| `sidekick.py` | App entry: buds link + gestures + modes + pipeline + dashboard; CLI |
| `dashboard/server.py`, `dashboard/web/*` | FastAPI REST + WebSocket and the UI |
| `eval/speaker_bench.py`, `eval/capture_kit.py` | Phase-0 measurement: synthetic benchmark; guided real-person capture |
